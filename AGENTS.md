# AGENTS.md

## Project

**emo** is a from-scratch Super Nintendo Entertainment System (SNES) emulator.

The implementation language and stack are not fixed yet. Check the local, untracked
`PLAN.md` before starting work and keep the roadmap there.

## Language rules

- All code, identifiers, comments, commit messages, UI labels and user-facing strings MUST be written in English.
- Keep commit messages short and follow Conventional Commits (`feat: ...`, `fix: ...`, `refactor: ...`, `chore: ...`).

## Code style

- Follow the canonical formatter and linter for the language in use, and run them
  before declaring any task done.
- Match the style and conventions of the surrounding code. When in doubt, prefer
  the simplest, most explicit solution.
- Keep modules small and single-purpose. Emulator components (CPU, PPU, APU, DMA,
  cartridge, scheduler, frontend) must not reach into each other's internals.
- Name things after the hardware they represent, using the standard SNES terms
  (CPU, PPU, APU, SPC700, DSP, DMA, HDMA, VRAM, CGRAM, OAM, WRAM).
- Prefer clear code over clever shortcuts. Correctness and determinism come
  first; optimize only with measurements.
- No dead code, commented-out blocks or leftover debug prints. Use the project's
  logging/trace facilities instead.
- Public APIs and non-obvious hardware behavior get a short comment explaining
  the "why" and the hardware reference used.
- Never commit ROMs, firmware dumps, secrets or other copyrighted binaries.

## Testing

- Keep the existing test suite green after every change.
- Prefer hardware test ROMs and deterministic frame/audio hashes for regression
  coverage.
- Add a regression test for every bug fix when practical.

## Committing and pushing

- Use short, imperative commit messages in English with a Conventional Commits prefix:
  - `feat: short message` - a new feature.
  - `fix: short message` - a bug fix.
  - `refactor: short message` - a change that neither adds a feature nor fixes a bug.
- Never add AI authorship or co-author trailers (no `Co-Authored-By`, no "Generated by ...", no tool/agent attribution). The commit author is the human contributor only.
- Stage only the intended files, then commit and push to the current branch.

```bash
git add <files>
git commit -m "feat: short message"
git push
```

## Releases

- Releases are created from GitHub Actions (`.github/workflows/release.yml`) via
  `workflow_dispatch`; never create release tags by hand.
- Pick a bump type (`patch`, `minor`, `major`, `prerelease`, `premajor`,
  `preminor`, `prepatch`) or provide an explicit `version`.
- The workflow resolves the next version from the latest `vX.Y.Z` tag, generates
  the release notes from Conventional Commits since that tag using
  `scripts/release-notes.js` and `docs/RELEASE_TEMPLATE.md`, pushes the
  `vX.Y.Z` tag and creates the GitHub release.
- Pre-release versions (containing a `-`) are published as GitHub pre-releases.
